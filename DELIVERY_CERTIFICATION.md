## Public hosting blocker
Two production deployments were created from the exact CI artifact. The deployment bootstrap verifies the artifact SHA-256 before unpacking it.

External GitHub Actions checks reached both Vercel aliases with HTTP 200, but the returned HTML was Vercel's authentication/dashboard page (`class=... dash`), not Beyond 90. Supplying `ssoProtection: null` in deployment project settings did not remove that project/team-level protection. The connected Vercel tool currently exposes no project-protection update action, and project reads return no projects for the connected team even though deployment creation succeeds.

Therefore:
- [x] External runner can resolve and reach the Vercel hostname.
- [ ] Anonymous request returns the Beyond 90 bundle rather than Vercel protection UI.
- [ ] Exact public URL can proceed to WebKit E2E.

No protected alias is to be released as a playable test URL.
